# CADG

CADG dialogue generation using supervised fine-tuning (SFT), direct preference optimization (DPO), and group relative policy optimization (GRPO).

This document lists the input files, output files, and model directories configured in the scripts in this folder. Entries reflect active file reads and writes. Outputs are configured destinations, not evidence that a training run has completed.

## Detailed inputs and outputs

Paths are written exactly as configured. Relative paths resolve from the working directory where a script is launched. A trailing `/` denotes a directory rather than a single file. Model checkpoint contents and filenames are generated by the training libraries.

### `2_1_SFT_cadg.py`

| Type | File or directory | Role |
| --- | --- | --- |
| Input | `models_in/dial_test_data_label_GPT.csv` | Labeled test dialogues; uses `patient_history`, `couns_question`, `CCD_feature_name`, and `dialogue` |
| Input | `models_out/CD_generated_vs_reference_F1.csv` | CCD detection results; reads the `Generated` column |
| Input | `models_in/instruction_ft_dialogues_data_train_v2_GPT.json` | Training data |
| Input | `models_in/instruction_ft_dialogues_data_val_v2_GPT.json` | Validation data |
| Output, then input | `models_in/instruction_ft_dialogues_data_test_v2_GPT.json` | Test JSON generated from the two CSV inputs, then loaded as a dataset |
| Model input | `unsloth/Meta-Llama-3.1-8B-Instruct-bnb-4bit` | Hugging Face base model and tokenizer |
| Output directory | `/N/slate/tnaduvil/models_save/Dial_SFT/` | Trainer checkpoints, under `checkpoint-<step>/` |
| Output file | `/N/slate/tnaduvil/models_out/dial_SFT_trainer_stats.csv` | Training and evaluation logs |
| Output directory | `models_out/Dial_SFT/lora_model_SFT_dial_gpt/` | Final adapter and tokenizer saved with `save_pretrained` |

The test JSON is overwritten when the preparation block runs. Despite a console message mentioning JSONL, the code writes a JSON array to the `.json` path above. The script loads all three dialogue JSON files. It does not export inference or F1 CSV files.

## Data and checkpoint handoffs

- **CCD results to CADG SFT:** CADG SFT requires `models_out/CD_generated_vs_reference_F1.csv`. No active export in the uploaded scripts produces that exact file; provide it separately or add a generation/export step.
- **CADG SFT to CADG DPO:** DPO expects `checkpoint-112` under the SFT checkpoint directory. Confirm that checkpoint exists, or update the path to an available checkpoint.
- **CADG DPO to CADG GRPO:** DPO exports `models_save/dial_DPO_lora_model/`, which GRPO loads directly.

## Path and data requirements

- The repository contains scripts and environment definitions. The datasets, trained models, and generated output files listed above are not included.
- SFT instruction JSON records use `instruction`, `input`, and `output` fields. DPO CSV files require `prompt`, `chosen`, and `rejected` columns.
- Absolute `/N/slate/tnaduvil/...` paths and environment prefixes refer to the original cluster setup. Adjust them for your system, and create parent directories for CSV and JSON exports before running.
- Checkpoint step numbers are configured inputs, not guaranteed outputs. Select checkpoints that exist after training.
- The environment YAML files contain Linux-specific package builds. They are environment specifications, not scripts that read datasets or generate training results.

Environment definitions are at the repository root: [`dpo_env.yml`](../dpo_env.yml) and [`grpo_env.yml`](../grpo_env.yml).
